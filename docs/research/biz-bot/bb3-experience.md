## 1. Purpose & architecture

The experience layer is the entire browser product: a **no-framework, no-build static SPA** (plain ES modules, served as Cloudflare static assets) that the user lives in. It turns the lower layers (the worker's unified `/api/*`, the local bridge `/local/*`, the Durable Object runtime `/api/runtime/*`) into three surfaces — **Conversations**, **Projects** (with Inbox) and **Admin** — plus a first-launch **template chooser** and a **Getting started** page. It owns all user-side persistence (localStorage for records, IndexedDB for chat logs, plan state, artifacts, apps and vectors), versioned record **sync** with the bridge/cloud runtime, the **voice/speech** I/O, the **document vector store**, the **MCP connector** registry, the **skill** library, sandboxed **in-app apps**, **artifact** previews, and every configuration screen.

Architecturally it is a "shell + late-bound controllers" design (`docs/ui-architecture.md`):

- `public/js/app.js` builds a single mutable `app` object (`app.js:54-66`): `session` state (`current: {kind:'bizbot'|'bot'|'swarm', convId, name|id}`, `catalog`, `connected`, `workspaceMode`, `navigationVersion`, `activeKey`, `projectTab`), shared containers (`views` = log key → chat DOM view, `runs` = log key → AbortController, `runDone`, `plans`, `planTimers`, `runnerInfo`, `artifactCache`, `projectCost`, `seenIdeas`…), and services (`store`, `vectorStore`, `artifacts`, `apps`, `drafts`, `engine` from swarm.js, `graph`, `runner`, `memorySync`, `notifier`, `botForm`, `projectView`, `runtime`/`local`/`cloud`).
- Seven controllers (`chrome`, `runs`, `conversations`, `projects`, `admin`, `share`, `setup`) are created with `createXController(app)` and `Object.assign`ed back onto `app` (`app.js:303`). They call each other only through `app.<fn>` so creation order doesn't matter.
- A hash router (`router.js`) *applies* external URL changes and lets controllers *reflect* state into the hash without re-entry loops.
- Pure render functions (`components/base.js` `html\`\`` tagged template with auto-escaping, `paint()` that preserves focus/selection/open details/scroll) keep UI testable in Node.

Main flow of one user message: composer `send()` (`controllers/conversations.js`) → `app.deliver({who, raw, images})` (`controllers/runs.js:198-250`) → `resolveConversation(who)` → slash-command intercepts (`/forget`, `/undo`, `/refine`, `/discuss`, `/plan`, `/skill` expansion) → per kind: Bizbot `engine.runDirectMessage({bot: routerBot(...), extraSystem: routingBrief(...)})`, one agent `runDirectMessage`, a team `runSwarmMessage` / `runDiscussion` / `runPlan` → streaming renders into that conversation's own view (even if the user navigates away) → `chatlog` append/update → finally: `chatlog.flush()`, desktop notification for CLI agents, AI-written title (`entitle`), busy UI refresh.

Boot (`app.js:306-352`): one-time migrations (strip TTS from builtin bots; legacy swarm transcripts → chatlog; `migrateLegacyLogs` → conversation records) → `connect()` (`/api/health`, catalog, version check with one-shot reload) → probe bridge and cloud in parallel → if fresh browser and a runtime is reachable, adopt its records by sync (`template: 'synced'`) → `ensureSetup` (apply pre-chosen template or show chooser) → `applyMode()` → render sidebar → hydrate plans → `router.start()` or restore `localStorage.lastOpened` → set `document.documentElement.dataset.booted = '1'` (the e2e readiness flag).

### 2.1 App shell, services wiring and boot — solid

### 2.4 First-launch template chooser & onboarding templates — solid
`public/js/templates.js`, `controllers/setup.js`, `components/template-chooser.js`, `public/templates/{index,personal-assistant,research,software,business-ops}.json`. A template is plain JSON: `principal` (name/title/tone/rules), `bots[]` (with `key`, `instanceOf:'principal'`, `tools`, `skills`, optional `prefer:'cli'`), `teams[]` (`key,name,goal,bots,coordinator,rounds`), `skills[]` (catalog names), `customSkills[]`, `connectors[]` (`{catalog:id}` or `{name,url}`), `automations[]` (`kind: schedule|page|file|docs`, `schedule:{everyMs|dailyAt}`, `action:{type:'skill'|'plan'|...}`, `team`, `gate`, `requires:'bridge'`), `apps[]`, `sampleProjects[]`, `starters[{title,prompt}]`. Pipeline: `validateTemplate` (unknown tools/skills/members/automations; the `system` tool is refused in templates) → `planApply` (creates vs skips, `needs.keys/bridge`) → `applyTemplate` (idempotent by name / `sourceTag = template:<id>#<key>`; never overwrites a user-edited principal; keyed connectors become `suggestedConnectors`; automations returned for queueing; `mode:'replace'` removes records an earlier template created) → `writeSetup({template, version, appliedAt, starters})` in `localStorage['bizbot:setup']`. Automations wait in `bizbot:pendingTriggers` until the runner is reachable (`flushPendingTriggers`). `ensureSetup` boot rule: no flag + existing bots → `legacy`; no flag + nothing → `welcome`; flag with template but no `appliedAt` → apply now. The chooser previews "Creates N agents: …", what is kept, what is still needed (a key, the bridge), an opt-in sample project, and the Simple/Full radio. The **business-ops** template (the most relevant to a business owner) creates Ops assistant (coordinator), Analyst, Planner, Writer as principal instances, an "Ops team", 7 skills, a disabled daily 08:00 review automation, a "Quarterly review deck" sample project and 4 starters. Tests: `templates.test.mjs` (every shipped template validates; applying twice is identical; export carries no secrets).

### 2.6 Conversation records (Bizbot / agent / project / channel) — solid
`public/js/conversations.js` + `store.js:23-32, 415-449`. Record: `{id:'conv_…', kind:'bizbot'|'agent'|'project'|'channel', title, titleSource:'auto'|'ai'|'user', botName, teamId, projectId, summary, pinned, archived, orphaned, legacyKey, createdAt, updatedAt, lastMessageAt, messageCount}`. Invariants enforced in `saveConversation`: an `agent` conversation needs an existing bot; a `channel` needs an existing team and is **unique per team** (and adopts the owning project id); a `project` conversation needs a project and derives `teamId`. The log lives in chatlog under `conv:<id>`; plans keep the team key `swarm:<teamId>` (shared with the bridge runner). `repairConversations` archives-as-orphaned any conversation whose agent/team/project disappeared rather than deleting history. `ensureBizbot()` returns the latest open Bizbot thread; `+ New chat` reuses an empty one instead of piling up blanks. Titles: `titleFrom(text)` (first line, command prefix stripped, cut at a word boundary, 60 chars) is written on first send; after the first turn `aiTitle()` asks the fastest configured model for a 2–6 word title (`max_tokens: 24`, never for mock; a user rename wins). Document scopes: `writeScope` (project → `project:<id>`, else `conv:<id>`, else `shared`), `readScopes` (shared + conversation + log key + `bot:<name>` + project + swarm + legacy key). `migrateLegacyLogs` is a one-shot, idempotent, copy-not-move migration of per-bot/per-room logs into conversations with a backup written to `state['backup:conversations-migration']`, and rescopes vectors and artifacts. Tests: `conversations.test.mjs`, `conversation-list.test.mjs`.

### 2.7 Bizbot router agent (the single point of contact) — solid
`public/js/bizbot.js`. `routerBot(store, catalog)` builds a **virtual** bot from the principal (never stored, cannot be deleted): tools `['ask_bot','memory','document_search','summarize_document','web_search','fetch_page','system']`, provider = principal's router provider → catalog default chat → first usable non-agent provider. `routingBrief(store, {plans})` is appended to the system prompt each turn: routing rules (answer simple things; delegate with `ask_bot`, possibly several in parallel, and integrate; for multi-step outcomes use `create_project` (asks first) or `propose_idea`; extend the system with `create_agent/create_team/install_skill/create_automation/add_connector`, checking `list_capabilities` first; never ask for keys), then a live roster of delegable agents with tools, standalone teams, and projects with status labels. This is the lead-orchestrator pattern in miniature.

### 2.10 Streaming chat rendering — solid
`ui.js addMessage()` returns a controller `{append, set, setLoading, setStatus, appendReasoning, addTool, addCitations, addImage, addAudio, addNote, addAction, remove}`. Text is re-rendered through markdown-it (`linkify`, `breaks`) + DOMPurify, throttled with `requestAnimationFrame`. Reasoning deltas go into a collapsible "Thinking…" `<details>`. Tool calls become **chips** (spinner → done/failed) with humanized names (`server › tool`, "(via room)" for relayed calls), live stdout/stderr streams trimmed to 400 lines and folded into "output while running", and a result summary line (`n results`, `hand-off queued for X`, `denied by user`, `spoken aloud`, …) over a nested JSON table (`formatValue`: every object/array becomes a Property/Value table in `<details>`, cycle-safe, depth ≤20, long strings folded, data URLs collapsed). Citations are deduped and capped at 5 with "+N more". `scrollToBottom` never scrolls a hidden view. `rich-content.js` watches the DOM with a debounced MutationObserver and lazily imports Mermaid 11.12.0 (`securityLevel:'strict'`, `htmlLabels:false`), sanitizes the SVG, keeps the source in "Diagram source" details, and on failure shows "Diagram preview unavailable … Retry". Persisted log entries are re-rendered on revisit via `renderEntry` with tags: "Saved draft · incomplete", phase, "via hand-off", "asked by X", "voice". Tests: `ux.test.mjs`.

### 2.11 Stream reliability and recovery — solid
`api.js readEventStream()` reads SSE with `reader.read()` (Safari-safe), with two budgets: **network idle** (`STREAM_IDLE_MS` = 10 min) and **provider progress** (`STREAM_PROGRESS_MS` = 20 min; only real events count as progress, keep-alives don't). On timeout it throws `StreamTimeoutError` "…Received output is saved as a draft; Resume to retry." `chatStream()` aggregates `{text, reasoning, tool_calls, citations, images, usage, session, finish}` and throws if no `done` event arrived. `turn-record.js createTurnRecord(log, fields)` appends a bot entry on the **first streamed text** marked `incomplete:true`, updates it as text arrives, and on failure keeps partial text + error; `downloadTurnOutput` saves any draft as Markdown. Incomplete entries are fed back to models as "[Saved incomplete draft — not completed work]" (`swarm.js:48-50`). `chatlog.update` debounces writes (150 ms) while `append` flushes immediately; `pagehide` flushes logs and aborts in-flight turns so they end as "stopped" rather than failures (`controllers/runs.js:25`). Tests: `stream-recovery.test.mjs`, `plan-checkpoints.test.mjs`.

### 2.12 Voice input (speech-to-text) — solid
`speech.js` + `controllers/conversations.js startMic()`. Push-to-talk mic button. Preferred path: **MediaRecorder** (`audio/webm;codecs=opus`, else `audio/mp4` for Safari) → `api.transcribe(blob, {provider: catalog.defaults.stt})` → worker `/api/transcribe` (multipart; `audioFilename()` maps mime → `recording.m4a|mp3|wav|ogg|webm`). Fallback: browser `SpeechRecognition` (interim results) — and if the native recognizer errors with language/not-allowed/network, it switches to the worker STT automatically. On a final transcript the message is **sent automatically**. Dropped audio files are also transcribed into the composer. Provider defaults (worker catalog order openai → xai): OpenAI `gpt-transcribe` (also `gpt-4o-transcribe`, `whisper-1`) or xAI `grok-stt`.

### 2.13 Text-to-speech (replies read aloud) — solid
`tools.js:162-176, 373-416`. A bot with the `text_to_speech` tool has **every reply spoken automatically** (`autoSpeak`, called from `swarm.js` after each turn) unless it already called the `speak` tool; `speak({text})` is also offered for extra passages. `ttsFor(bot, catalog)` resolves `bot.voice {provider, voice}` → worker default TTS. `speakable()` strips Markdown, code fences ("(code omitted)"), links, tables, URLs → "link", capped at ~3000 chars at a sentence boundary. The audio blob from `/api/speech` is appended to the message as an `<audio controls>` element and autoplayed; on autoplay rejection (iOS) a one-time toast says "Tap ▶ on the reply to hear it" and the player gets `.needs-tap`. The system prompt tells TTS bots to "write for the ear" (`agent.js:79-80`). TTS is deliberately excluded from rooms/assembled teams ("six bots reading themselves aloud in a room is not useful", `assemble.js:41`) and was stripped from builtin bots at boot. Voices: OpenAI `gpt-4o-mini-tts` (default; `tts-1-hd`) with voices marin, cedar, alloy, ash, ballad, coral, echo, fable, onyx, nova, sage, shimmer, verse; xAI `grok-tts` with 26 voices (eve, ara, leo, rex, sal, carina, … atlas). Tests: `spa.test.mjs` "text-to-speech: replies of a TTS bot are spoken automatically (markdown stripped), not twice, and never without the tool".

### 2.14 Realtime voice conversation (xAI, beta) — partial
`voice.js startVoiceSession()` + `controllers/conversations.js` voice button. The worker mints an ephemeral client secret (`POST /api/realtime/token {provider:'xai', expires:300}` → xAI `POST /v1/realtime/client_secrets`); the browser then opens `wss://api.x.ai/v1/realtime?model=grok-voice-latest` with subprotocol `xai-client-secret.<secret>` — audio never touches the worker. Protocol is OpenAI-Realtime-style: `session.update` (instructions, `voice` default `eve`, `turn_detection:{type:'server_vad'}`, PCM 24 kHz in/out, function tools + native `web_search`/`x_search`), `input_audio_buffer.append` (mic → ScriptProcessor 4096 → downsample to 24 kHz → Int16 → base64), handles `input_audio_buffer.speech_started` (**barge-in**: drops queued playback), user transcript events (deduped), `response.output_audio_transcript.delta`, `response.output_audio.delta` (scheduled gapless playback via a playhead), `response.function_call_arguments.delta/done` and `response.output_item.done` → runs the **same browser tool runners** as text chat and returns `function_call_output` + `response.create`. Status callbacks: connected / listening / speaking / closed. Transcripts and tool chips are persisted to the chat log as `voice:true` entries. Limitations: xAI only; button shown only for single-agent chats (hidden for Bizbot and rooms); uses deprecated `ScriptProcessorNode`; no reconnection; README labels it beta.

### 2.15 File ingestion, attachments and media — solid
`files.js`, `controllers/conversations.js addFiles`. Drag-and-drop anywhere or the upload button. `readAnyFile` → `{name, type, content, kind, size, blob, originalUrl}`: PDFs → text via **pdf.js 4.10.38** (lazy CDN import from cdnjs; `[Page n]` markers, line breaks by y-position) plus the original as a data URL; images → data URLs (attached to the next message for vision models); audio → data URL + transcription; video → data URL; known text/code extensions → text; everything else → opaque file. Each drop is logged as an `attachment` chat entry (original bytes preserved for preview/download). With the bridge online the file is saved to `<workspace>/inbox/<name>` and registered as an artifact (`source:'upload'`). Videos: with the bridge + ffmpeg, `extractVideoFrames` runs ffprobe/ffmpeg in the sandbox to cut ≤12 (default 6) evenly spaced 640px JPEG frames that are attached for vision models and saved as `frame` artifacts. Text documents are chunked and embedded into the vector store with a live "Indexing… n/m chunks" note and a hidden note entry telling the model which tools can read it. Two or more images/frames trigger a toast "Turn this demonstration into a reusable skill" → `draftSkillFromDemo` (a vision model with a JSON schema writes `{name, description, when, instructions}`). Attachment text also reaches the model directly as bounded (32k total, 16k per file), `wrapExternal`-framed untrusted content (`swarm.js:34-54`).

### 2.16 File preview and rich previews — solid
`file-preview.js`. `filePreviewHTML` renders images, audio, video, **PDF pages via pdf.js canvas** (prev/next, DPR-aware, page text as aria-label), JSON as nested tables, CSV via a real RFC-style parser (quoted commas, escaped quotes, multiline cells, CRLF; first 200 rows), Markdown/Mermaid/text via the markdown renderer, code as `<pre>`, and "no built-in viewer — download the original" for binaries. `openFilePreview` is an accessible modal (focus trap on Tab/Shift+Tab, Escape, restores focus, revokes object URLs, "Download original").

### 2.17 Artifacts — solid
`artifacts.js`. Everything produced is an artifact `{id, key, kind, title, filename, mime, path, url, size, projectId, chatKey, by, runId, taskId, source, note, at, hasContent}` with `ARTIFACT_KINDS = document|web|code|image|screenshot|audio|video|frame|file|data`, `kindOfFile`/`mimeOf` from extensions (xlsx, pptx, docx, py, …). Index stored at `state['artifacts:index']` (≤1000), contents at `state['artifact:<id>']`; `add()` is idempotent by `key` (refresh instead of duplicate). Producers: `fromDeliverable(plan)` (plan result), `fromMedia(task)` (speech steps), `fromImage(src)` (generated images, screenshots), `fromFile({path})` (workspace files). `artifactsFromText()` harvests `Artifact: <path>` lines agents write in replies. `openArtifact` previews: images, audio, video, **web artifacts running in a sandboxed iframe** (`allow-scripts allow-forms allow-modals allow-popups`, srcdoc), PDFs, Markdown, code; workspace files are read through the runtime; Download for anything with content or URL. Artifacts are listed per project (Artifacts tab) and as Recent artifacts on the home. Tests: `artifacts.test.mjs`.

### 2.18 Apps within the app (sandboxed mini-apps) — solid
`apps.js` + `app-host.js` + `controllers/projects.js openApp`. An app is single-file HTML (≤1 MB; ≤20 per project) stored at `state['app:<id>:html']` with a record `{id, name, icon, kind:'web', version, source:{artifact, workspace}, permissions ⊆ ['storage','artifacts','chat','tools'], projectId, pinned, draft, createdBy, size}` in `state['apps:index']`, and a per-app KV store `state['app:<id>:storage']` (≤256 KB). Created by agents (`create_app` system tool → draft) or **Install as app** from a web deliverable (`installFromArtifact`, non-draft, `['storage']`). Hosting: `<iframe sandbox="allow-scripts allow-forms allow-modals" srcdoc=…>` (opaque origin, no same-origin, no popups/navigation), `referrerpolicy=no-referrer`, and an injected CSP `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; media-src data: blob:; connect-src 'none'; form-action 'none'; base-uri 'none'` → **no network**. An injected SDK exposes `window.bizbot = {version, chat(text), artifacts.{list,read}, storage.{get,set}, tools.call(name,args), app.info()}` over `postMessage({bizbot:1, id, method, params})`. `createAppBridge` answers only its own frame, checks declared permissions, allow-lists tools (`list_artifacts`, `read_artifact`, `list_bots`), rate-limits (30 calls / 10 s) and caps results (1 MB). `chat` and `tools.call` show an **approval card inside the app modal** (Allow once / for this chat / Deny) before anything reaches Bizbot; an approved `chat` is delivered to the Bizbot conversation as "[From the app “X”] …". ### 2.20 Document vector store and embeddings — solid (brute force)
`vectors.js`. IndexedDB `gpt-spa-vectors` v1, store `chunks` (keyPath `id`, indexes `doc`, `scope`). `chunkText(text, 900, overlapSentences=1)` sentence-splits with one-sentence overlap. `storeDocument(name, text, scope, onProgress)`: chunk id `${scope}::${name}::${sha256(chunk)[:12 bytes]}`; skips re-embedding when all chunks exist with the same model (confirmed by embedding a probe chunk to detect an embedder switch); otherwise embeds in batches of 32 and stores `{id, doc, scope, index, text, embedding, model}`. `search(query, {scopes, count=5, minScore=0.2})` embeds the query and does **brute-force cosine** only over records with the same `model` tag and dimension. ### 2.26 Local store, versioned sync (protocol 2) and backups — solid (with bugs)
`store.js`, `sync.js`, `runner.js sync()`. Every write to a synced collection (`bots, swarms, projects, projectDecisions, skills, grants, ideas, mcpServers, principal, conversations, systemChanges`) is diffed against a JSON snapshot; changed records get `syncMeta[coll][id] = {rev+1, updatedAt, deletedAt?}` and a changelog entry `{seq, coll, id, rev, at, deleted?, by: clientId}` (≤2000 entries; tombstones kept 30 days). `changesSince(seq, {exclude})` returns deltas with current records (connector headers redacted); `applyChanges(changes, {from})` merges with `mergeRecord`: newer `updatedAt` wins, tie → higher `rev`, tombstones are records (a later edit resurrects), and a **resolved decision always beats a pending one**. ## 5. UX details worth keeping

- **One conversation = one living view.** Switching conversations never interrupts a stream; the task dock shows what is running and lets you stop or close each; drafts and attachments are per conversation and survive reload.
- **Empty-state as onboarding.** A new chat shows template starters, a scenario library, a one-tap line to every agent, and unfinished setup steps — onboarding lives where the user already is.
- **Simple ↔ Full.** A business owner can run the whole product through Chat · Projects · Inbox · "+ Delegate a project"; power features are one toggle away and the chooser proposes the right default per template.
- **Turn into project** from any conversation's ⋯ menu or from Bizbot's reply: the conversation's context carries into the project.
- **Honest partial output.** "Saved draft · incomplete" tags, timeout messages that say what was saved and how to resume, and Markdown download of any draft.
- **Readable tool activity.** Humanized chip names, live stdout, one-line summaries, and structured JSON tables instead of raw blobs; citations capped with "+N more".
- **Voice affordances.** Push-to-talk that auto-sends on the final transcript; replies with an inline audio player and autoplay fallback; realtime voice with a status line (listening/speaking) and barge-in.
- **Pending credentials as a visible state.** Connectors appear with a "needs a key" tag and an inline field; "Add the key later" is a first-class choice; the model never sees tokens.
- **Approval cards everywhere with scoped grant options** (once / this task / this chat / 24 h / always) and a diff card with evidence for proposed changes; the in-app-app approval strip lives inside the app modal.
- **Undo for everything the AI changes** (message-level Undo action, `/undo`, Admin → Activity).
- **Magic wand fields** that stream in or offer Replace/Append/Discard, plus silent completion of blank optional fields with a "Review" toast.
- **Memory you can read**: Markdown editor with per-scope files, "Forget everything about…", and reflection proposals that go to the Inbox instead of silently rewriting.
- **Accessibility**: focus-trapped preview dialogs, Escape everywhere, `aria-expanded` menus with arrow-key navigation, `/` to search, reduced-motion support, PDF page text exposed as aria-labels.
- **Resilience cues**: API dot, bridge dot with tooltip of capabilities, banners with the exact command to fix the problem, version-skew auto reload.

## 6. Patterns worth reusing

1. **Conversation records as first-class objects with typed kinds** (`store.js:23-32`, `conversations.js`). Lift directly: kinds `lead` (the chief-of-staff thread), `agent` (DM with one coworker), `project` (the user with a project team), `channel` (the team's own room where hand-offs, plans and automations post; exactly one per team). Add `meeting` for live multi-avatar sessions. Keep invariants in the save path and "archive as orphaned" rather than cascade delete.
2. **Virtual lead agent + per-turn routing brief** (`bizbot.js`). The lead is derived from the principal profile (undeletable) and gets a fresh brief each turn listing delegable agents, teams and projects with status. In the Agent Workplace, generate this brief from the project/plan store and add avatar/voice identity to the principal.
3. **Principal + instances persona layering** (`store.js normalizePrincipal`, bot `instanceOf`). One shared personality (tone, preferences, standing rules, voice, proactivity) with specialist instances that differ only by specialty and skills; standalone personas remain possible. Extend with face/avatar rig ids and per-persona voice ids.
4. **Unified SSE event protocol + dual-budget stream reader** (`api.js:93-174`). `readEventStream` with network-idle vs provider-progress budgets and "missing `done` = error" is a solid primitive for long-running agent turns; add `viseme`/`audio` event types for avatar lip-sync.
5. **Turn records that checkpoint on first token** (`turn-record.js`) and "incomplete draft" framing when replaying history to models (`swarm.js:48-50`). Essential for multi-agent runs where any member may stall.
6. **Per-conversation persistent views + task dock** (`controllers/conversations.js viewFor/renderTaskDock`). Maps directly to "navigate, view, join any agent while others keep working": each agent/meeting gets a mounted view; a global dock shows who is speaking/working.
7. **Ephemeral-token realtime voice with browser-side tool execution** (`voice.js`). The worker mints a short-lived secret; audio flows browser↔provider; function calls run through the same tool runners as text. Reuse for the lead agent's voice mode; add an OpenAI Realtime/Gemini Live adapter behind the same event handler, replace `ScriptProcessorNode` with an AudioWorklet, and tap the output PCM for amplitude/viseme estimation to drive avatars.
8. **TTS policy objects** (`tools.js ttsFor/speakable/autoSpeak`): per-persona voice resolution with fallback, Markdown-to-speech cleaning, "speak automatically unless the agent already spoke", and "no auto-TTS in rooms". In the Workplace, rooms should instead queue speech with a floor-control model (one avatar speaks at a time; the user can "listen in").
9. **Memory as Markdown with id comments + echo-safe file sync** (`memory-files.js`, `memory-sync.js`). Human-editable, diff-friendly, scope per file, "file wins unless app is newer", compaction as a reviewable diff. Reuse for business context ("company.md", "project-<id>.md") and store in R2/D1 in the cloud.
10. **Model-tagged vector records** (`vectors.js`): never compare embeddings from different models; hash-based chunk ids make re-indexing idempotent. Swap brute-force IndexedDB for Cloudflare Vectorize/D1 at scale, keep the scope model (`shared`, `project:<id>`, `conv:<id>`, `bot:<name>`).
11. **Connector catalog + token-pending state + transport routing** (`connectors.js`, `catalog.json`). JSON catalog with `auth` kinds and hints, `authPending` records, secrets redacted from sync, `mcpTarget()` choosing cloud vs local bridge by URL privacy. Add a real OAuth 2.1/PKCE flow for MCP servers and a server-side secret vault.
12. **Sandboxed apps with a tiny postMessage SDK** (`app-host.js`, `apps.js`): opaque-origin srcdoc iframe, injected CSP with `connect-src 'none'`, permissioned methods, allow-listed tools, rate limit, result caps, approval strip. Perfect for agent-built dashboards inside projects.
13. **Artifact registry with idempotent keys and producers** (`artifacts.js`), including the `Artifact: <path>` reply convention for agents to declare outputs.
14. **Versioned record sync with changelog, tombstones and domain-aware merge** (`sync.js`, `store.js:171-198, 469-514`): LWW by `updatedAt`→`rev`, "resolved decision beats pending" — a good template for D1/Durable Object sync of agent-workplace records across devices.
15. **Templates as validated, idempotent JSON with source tags** (`templates.js`) and **mode defaults per template** (`mode.js`). Reuse for industry starter kits (agency, e-commerce, consulting), each seeding personas, teams, skills, connectors, automations and starters.
16. **No-framework component discipline** (`components/base.js`: escaping `html` tag, `paint()` preserving focus/selection/details/scroll, `delegate`, `keyedList`, import-safe modules tested in Node). Even if the Workplace uses a framework, keep "pure render + controller owns state" and the stable selector contract for e2e.
17. **Annoyance budget + desktop notifications only when hidden** (`app.js ping`, `notify.js`). A business owner surrounded by agents needs interruption rationing.
18. **AI auto-fill with field kinds and budgets** (`autofill.js`) for every configuration form (persona bios, project scope, success criteria).

## 7. Gaps, debt & risks

- **Backup export/import drops conversation records (likely bug).** `settings.js:471` builds `{ ...store.exportAll(), backupVersion: 1, conversations: await chatlog.exportData() }`, which overwrites the store's `conversations` array with the chat-log export `{logs, state}`. On import `store.importAll` only restores conversations when `Array.isArray(data.conversations)` (`store.js:705`), so titles/kinds/bindings are not restored even though `conv:<id>` logs are.
- **Data export contains connector tokens and is not labelled as such.** `store.exportAll()` includes `mcpServers` with `headers.Authorization` (only the local pairing token is excluded). Templates export is secret-free, but `biz-bot-export.json` is not.
- **Secrets at rest in localStorage.** Connector tokens and the bridge pairing token are plain localStorage values; any XSS would expose them. The SPA itself has no CSP (only `X-Frame-Options`, `nosniff`); third-party scripts load from CDNs without SRI.
- **OAuth connectors are docs-only.** Notion, HubSpot, QuickBooks, Xero, Asana, monday.com, Calendly and Canva are declared `auth:'oauth'` with "signs you in the first time" hints, but no OAuth flow exists; they stay pending unless a token is pasted.
- **Share-link import trusts the payload.** A shared bot is saved with its `trust` overrides (e.g. `commands:'auto'`) and coding-agent `permissionMode` (e.g. `bypassPermissions`); only a name collision prompts. Legacy hashes import on page load.
- **App approvals don't persist grants and non-project apps see all artifacts.** `openApp` offers "Allow for this chat" but never records a grant (each call re-asks). `listArtifacts({projectId:''})` and `readArtifact` with an empty project id apply no scope, so an app not bound to a project with the `artifacts` permission can read every artifact.
- **Realtime voice is narrow**: xAI only, single-agent chats only (hidden for Bizbot and rooms), deprecated `ScriptProcessorNode`, no reconnect or resume, no push-to-talk mode, transcripts only.
- **No avatars/visemes.** Avatars are uploaded images or a letter badge coloured by provider (`ui.js avatarHtml`); there is no animation, lip sync or expression system. The "speaking" signal exists only as graph halos (other slice).
- **Multimodal gaps**: no video generation; the image-edit endpoint exists server-side but has no client caller; the README says "paste images" but there is no `paste` handler (drag-drop and upload only); no camera/screen capture.
- **Vector store scalability**: all chunks are loaded into memory and scanned brute-force; embeddings live only in one browser (the README says indexes are rebuilt on another browser); no hybrid/BM25 search, no reranking.
- **chatlog caps at 500 entries per log**, silently truncating long-running channels; `searchLogs` is substring-only.
- **Conversation `pinned`, `summary` and `archived` fields** exist in the schema, but this slice has no UI to pin or archive a thread by hand (only orphaning archives), and nothing populates `summary`.
- **Usage display is minimal**: per-reply cost notes only when the provider reports cost; no per-agent/per-provider dashboard or budget view in the experience layer.
- **localStorage size limits**: avatars (data URLs), bot files and memory all live in localStorage; large setups risk quota errors (`persist()` does not catch them; `chatlog.setState` does warn).
- **Global mutable `app` object with late binding** is flexible but hard to type and reason about; controllers are 450–700-line files with inline HTML strings (settings.js is 492 lines of templated markup).
- **Pairing token in the URL** (`#/pair?url=…&token=…`) lands in browser history; the QR/links are LAN-only by design.
- **Mixed legacy naming** (bots/rooms/swarms vs agents/teams, "Settings" vs "Admin" in strings and toasts) remains throughout.

## 8. Relevance to the Agent Workplace

| Pillar | What biz-bot's experience layer offers | Adopt / adapt / avoid |
|---|---|---|
| **P1 Lead orchestrator** | Virtual `routerBot` from the principal + per-turn `routingBrief`; Bizbot conversations; "Turn into project"; system-tool self-extension surfaced as Undo actions. | **Adopt** the virtual-lead + live brief pattern; **adapt** so the lead also narrates delegations aloud and hosts meetings. |
| **P2 Personas** | Principal (name, tone, preferences, rules, proactivity, voice, avatar image) with instances; bot form with presets, voice provider/voice, reasoning, tools, skills, files; AI auto-fill. | **Adopt** principal/instance layering and presets; **extend** with face rig, expression palette, speaking style, and voice id per persona. |
| **P3 Avatars** | Only static image/letter avatars; TTS audio elements; realtime PCM playback with a playhead; speaking state exists elsewhere. | **Build new**: drive visemes from TTS/realtime audio (amplitude or provider timestamps), reuse the playhead scheduler and barge-in logic from `voice.js`. |
| **P4 Workflow** | Composer slash commands (`/plan`, `/discuss`, `/refine`, `/forget`, `/undo`, `/skill`), stream recovery, templates with automations, skill workflows. | **Adopt** recovery/checkpoint UX; engine lives in other slices. |
| **P5 Intra-agent comms** | Channel conversations per team, @mention and /discuss chips, hand-off notes, relay chips "(via room)", team chats listed in the sidebar. | **Adopt** channel-per-team and "watch the room" views; **add** avatar meeting rooms where the user can join and listen with floor control. |
| **P6 Projects** | Project conversations with context; Simple-mode tabs; Inbox badge; artifacts, apps, workspace folders `inbox/artifacts/apps/notes`. | **Adopt** the project-scoped conversation and artifact/app registries. |
| **P7 LLM providers** | Catalog-driven provider/model pickers, local providers merged with offline state, `reconcileBots` fallback, fastest-model titles, best-model autofill. | **Adopt** catalog-driven UI and capability flags; add Google/Gemini, which biz-bot lacks. |
| **P8 Multimodal** | STT (worker/native), TTS with auto-speak, realtime voice (xAI), image generation, PDF/CSV/JSON/media ingestion and previews, video frame extraction, embeddings, demo-to-skill from screenshots. | **Adopt** ingestion/preview stack and STT/TTS policies; **add** multi-provider realtime, camera/screen capture, image edit, video generation, paste. |
| **P9 Context & memory** | Scoped memory facts, Markdown memory files with sync, reflection/compaction via Inbox, scoped vector store, bounded untrusted attachment context. | **Adopt** Markdown memory and scope model; **move** vectors server-side (Vectorize/D1) and add a business-context file. |
| **P10 Tools/connectors/MCP/apps** | MCP catalog of 11 business services with token-pending state, remote vs bridge routing, Test connection, per-call approval; skills catalog (14); sandboxed apps SDK. | **Adopt** catalog + pending model + app sandbox; **fix** OAuth, server-side secret storage, app artifact scoping. |
| **P11 Navigation & UX** | Hash router with reflect/apply, Simple/Full, sidebar grouped by day with search, task dock, empty-state onboarding, Getting started, 14-section Admin with help, mobile visual-viewport fit. | **Adopt** Simple/Full, task dock and empty-state patterns; **replace** the flat sidebar with a spatial "office" view of avatars while keeping the list as a fallback. |
| **P12 Trust & governance** | Approval cards with scoped grants, Trust & grants admin, Activity audit with Undo, annoyance budget, desktop notifications only when hidden, secret redaction in sync. | **Adopt** grants/undo/annoyance budget; **avoid** localStorage secrets, unscoped share-link imports, and token-bearing exports. |
| **P13 Business** | Starter templates (business-ops is the closest fit), sample projects, project ideas, scenario library, share links (bot/conversation/room), export/import setup. | **Adopt** templates and share links (with sanitisation); add billing/guest links, which are absent. |
| **P14 Infrastructure** | Static SPA with `_headers` cache policy and version-skew reload, import-safe modules unit-tested in Node, stable e2e selector contract, boot flag for Playwright, versioned sync protocol 2 with a bridge and a Durable Object. | **Adopt** the sync protocol, boot flag, cache/version strategy and Node-testable pure modules; add a CSP and SRI. |

**Bottom line:** biz-bot's experience layer is a mature, well-tested reference for the *chat-and-admin* half of the Agent Workplace. It covers the lead agent entry point, per-agent and per-team conversations, resilient streaming, voice I/O, memory and connectors, and it is built from pure, portable modules. What it lacks is the *embodied* half: animated avatars, multi-party voice meetings, spatial navigation and multi-provider realtime. Those need to be built on top of its voice pipeline (`voice.js`, `tools.js` TTS) and its conversation/channel model. Before reuse, fix the backup bug, move secrets server-side, implement OAuth for the business connectors and scope app artifact access.
